# DeepSeek 悬浮球

浏览器扩展（Manifest V3）：任意网页上有一个 DeepSeek 鲸鱼悬浮球，可拖动、有惯性、鼠标碰到放大、用力丢向边缘会吸住；**双击打开一个对话面板**，直接问 DeepSeek。

## 文件结构

**根目录只放运行必需的东西**，加载扩展时选这个文件夹就行（`chrome://extensions` → 加载已解压的扩展程序）：

```
floating-ball/                 ← 加载扩展就选这一层
├── manifest.json        清单：注入规则、权限、后台脚本、设置页入口
├── config.js            ★ 你要填的文件：**我的人设**（API Key 不在这儿了，见下）
├── options.html         设置页空壳 + options.js：API Key 在这儿配
├── i18n.js              中英文词表：设置页 + 对话面板共用（面板的 key 前缀是 p.）
├── panel.js             对话面板（界面 + 历史记录 + 流式请求 + 读网页 + 取 Key）
├── content.js           悬浮球本体（拖动 / 惯性 / 吸附 / 双击开面板）
├── sidepanel.html       侧边栏那页：把面板装进浏览器右侧栏（点工具栏图标开）
├── sidepanel.js         告诉面板"你在宿主容器里跑"，然后打开它、铺满整栏
├── background.js        后台脚本：截当前可见的一屏 + 工具栏图标开侧栏 + 首装提醒配 Key
├── icons/               工具栏图标 16 / 48 / 128（清单里引用）
├── README.md            就是本文件，不影响运行
└── docs/                预览图与素材，不影响运行，整包删掉扩展照样能跑
    ├── index.html       ← 在浏览器里打开它，所有效果图一页看完
    ├── deepseek-logo.svg  图标源文件（Simple Icons 收录的 DeepSeek 品牌图形）
    ├── selftest.html    ← 自检页：无头 Chrome 打开它，真跑 panel.js / content.js 并逐项断言
    ├── selftest-sidepanel.html  ← 同上，专门验侧边栏（宿主模式）那套行为
    ├── selftest-key.html        ← 同上，专门验 API Key：设置页存进去、面板发请求时带出去
    ├── test-render.js   ← node docs/test-render.js：单测正文的 markdown 渲染 / 复制文本
    └── shots/           各版本的效果截图
```

> 上面这 9 个文件 + `icons/` 就是扩展的全部。`README.md` 和 `docs/` 都只是给人看的，
> 你要打包上架的话可以先把它们排除掉。

三个 js 都是 content script，按 `config.js → panel.js → content.js` 的顺序注入，
跑在同一个隔离环境里，所以能直接互相调用（`window.__dsPanel` / `window.__DS_BALL`）。
`background.js` 是唯一的 service worker，干三件事：截图、让工具栏图标点一下开侧栏、
首装/更新后如果还没配 Key 就把设置页打开（原因见下方"可见区模式"和"配 API Key"）。

## 配 API Key（在浏览器里，不写在代码里）

**Key 不在任何文件里。** 三个入口进同一个设置页：

1. 面板右上角 **⚙**（没配 Key 时它是橙色的，点一下就去配）
2. `chrome://extensions` → 本扩展 → **扩展选项**
3. 第一次装/更新完，如果还没配，扩展会自己把设置页打开

进去把 key 粘到输入框（密码型，旁边有「显示」），点**保存**。旁边还有**测试连接**——
它会拿你填的这串真打一次接口（`max_tokens: 1` 的 ping，几乎不花钱），通了会说"✓ 通了"，
401 会直接告诉你"Key 不对"，省得你在面板里发一条消息才发现。

- 申请 / 管理 Key：<https://platform.deepseek.com/api_keys>
- 存在 `chrome.storage.local`：**只在本机这个浏览器的扩展里**，网页读不到它（不是 cookie，
  也不是 localStorage）。只有发请求那一刻才取出来放进 `Authorization` 头，直接发给 `api.deepseek.com`，
  不经过任何第三方。
- 说清边界：`chrome.storage.local` 是明文的，跟 Chrome 存密码一个性质 —— 防的是"key 被写进代码、
  文件夹一复制/一备份就跟着走"，不是防"能摸到你这台电脑的人"。
- 所以这个文件夹**整个发给别人也不带 key**。要分享扩展时不用再翻一遍代码找有没有漏。
- 面板每次发送前会重读一遍 Key：你在设置页改完，回面板**直接就能用**，不用刷新页面。

### 界面语言：中文 / English

设置页右上角有个下拉，选一次就记住了（存在 `chrome.storage.local` 的 `__ds_lang__`，
下次打开还是这个语言）。**设置页和对话面板一起换**：

| 设置页（中文 / English） | 对话面板（中文 / English） |
|---|---|
| ![中文设置页](docs/shots/options-zh.png) ![English settings page](docs/shots/options-en.png) | ![中文面板](docs/shots/panel-zh.png) ![Chat panel English](docs/shots/panel-en.png) |

几条边界，免得你以为是坏了：

- **切完立刻生效。** 面板开着的话会当场重建（`relang()`）—— 输入框里还没发出去的字、
  抽屉开着没开、搜索词、滚动位置都先记下来再放回去。正在吐字的那一轮不动，等它写完。
- **只翻"给你看的"。** 拼进请求体的那些标记（`【附件 …】` / `【当前网页：…】`）**不翻**：
  它们是喂给模型的，跟着界面语言变会让模型看到中英混着的历史。同理，划词动作和
  `config.js` 里你自己写的提示词也不动。
- **默认标题「新对话」在存储里是固定值**（代码靠它判断"这条还没起名"），界面上按语言显示成
  New chat，但存进去的值不变 —— 变的话老记录和判断逻辑都会对不上。
- **思考档位的名字**默认取 `config.js` 的 `label`；只有英文界面才用词表顶替，
  你在 config 里自己加/改的档位不会被翻。
- **回答语言跟提问走，跟这个下拉没关系。** 你用中文问就中文答，用英文问就英文答；
  想让它固定用英文，改 `config.js` 里 `assistant.prompt` 那句（人设提示词在那儿）。
- 词表在 `i18n.js`（`zh` / `en` 两份，key 一一对应）：设置页的 key 不带前缀（`key.label`），
  面板的是 `p.*`（`p.send`）。**缺词会自动回落中文**，不会把 key 本身露到界面上。
  加第三种语言：加一个顶层键，再在 `options.js` 的下拉里加一行。
- 设置页的文案走 `data-i18n` 属性；面板是 `build()` 时一次性拼 innerHTML，所以直接调
  `tr('p.xxx')` 取词。**`<code id="dso-legacy-val">` 那个节点必须留在模板外面** ——
  它要是在被翻译的那段 html 里，每换一次语言节点就被重建，`el` 里抓着的是旧的，那一行会永远空着
  （自检里专门有一条盯着这个）。

> **从旧版升上来的**：以前 key 写在 `config.js` 的 `apiKey` 里，那条路仍然认（浏览器里没存就用它），
> 所以升级不会中断。设置页会认出这种情况、弹一张卡片并把值**预填进输入框**，点「搬进浏览器」
> 就把 key 搬进 Chrome 了 —— 之后把 `config.js` 里 `apiKey` 那行清成 `''`（或整行删掉），
> 文件里就彻底没有 key 了。

同一个文件里还有 `assistant` 段，是**我自己写进去的**：面板标题、系统提示词都在那儿。
想让我换个说话方式（更啰嗦 / 更简短 / 换个名字），改 `prompt` 和 `name` 就行。

> 面板按 DeepSeek 官方接口走。代码里另留了 `apiPath` / `requireKey` / `headers` 三个字段的口子
> （在 `panel.js` 里读，`config.js` 里没写就用默认值），真要接别的 OpenAI 兼容后端时才需要动它们——
> 那就得同时把 `manifest.json` 的 `host_permissions` 加上对应域名。现在这份配置就是纯 DeepSeek。
>
> 面板里的「Nova」是**人设**而不是模型：名字、称呼、系统提示词都在 `assistant` 段，真正干活的是
> `models` 里选中的那个模型。

## 安装 / 更新

1. `chrome://extensions` → 开发者模式
2. 首次：「加载已解压的扩展程序」选本文件夹；已装过：点卡片上的**刷新按钮**
3. 刷新任意网页（`F5`），球出现在右侧约 60% 高度
4. 配 API Key：面板右上角 **⚙**（没配的话扩展会自己把设置页打开），粘进去点保存

> **第 3 步不能省。** 扩展刷新后，已经打开的页面里跑的还是旧脚本——旧脚本失去了扩展上下文，
> 一碰 `chrome.storage` 就会抛 `Uncaught (in promise) Error: Extension context invalidated`，
> 这就是 `chrome://extensions` 里那条报错的来源（不是功能坏了）。
> 现在代码里已经兜住了：不再抛错，改成在你发消息时提示「按一次 F5 就能继续用」。

## 用法

| 操作 | 结果 |
|---|---|
| 双击球（轻点两下） | 打开对话面板，球自动收起 |
| **Alt + 空格**（可在 Chrome 里改） | 开 / 收面板；新标签页、设置页、PDF 这些「球进不去」的地方，按它会开右侧栏 |
| **Alt + Q**（同上） | 把网页上**选中的文字**送进面板：挂成一块蓝色 chip，**不自动发送**，等你补一句 |
| **把文件 / 文字 / 图片拖到球上** | 弹出**小窗**（全窗的一半），内容自动就位，直接提问 |
| **在面板里 Ctrl+V** | 剪贴板里的截图/图片直接进附件 —— 不用先存成文件（纯文字还是正常粘贴） |
| **选中网页文字** | 选区旁边冒出一行小动作（问 Nova / 翻译 / 总结 / 解释代码 / 改写 / 提取要点），点一下在面板下面挂一块蓝色 chip，**输入框留给你自己写**，发送时才带上 |
| **鼠标移到某条提问上 → 「回到这里」** | 丢掉这条和后面所有内容，把这条的文字**放回输入框**（改一句再问一次）；会先弹一层确认，写清要丢几条、图片回不来 |
| **鼠标移到某条回答上 → 「重试」** | 用**同样的上文**重新生成这条回答 —— 问题不动，只换答案。它后面还有内容时会先确认（那些会被一起丢掉）。和上面那行的区别：那个改**问题**，这个换**答案** |
| **在输入框里按 ↑ / ↓** | 光标在第一行时按 ↑：把上一条自己发过的话填回输入框（继续按往回翻），↓ 往回走、翻过最新一条就把你刚打的半句还回来。像终端一样 |
| 鼠标停在某条消息上 | 底部那行 `21:36` 是这条是什么时候说的（悬停看完整日期时间） |
| 右上角 ⚙ | 打开设置页配 API Key（不写在代码里） |
| 设置页右上角「界面语言」 | 中文 / English 二选一，选过就记住；**设置页和对话面板一起换**，切完当场生效 |
| 右上角 ¥（卡片图标） | 查账户余额：走官方只读接口 `GET /user/balance`，**不花 token、不花钱**，结果显示成一句提示 |
| 「推荐图片」开着时 | 每轮回答末尾多一行「配图」，几个能搜到相关配图的词 —— 点一下新标签页里搜图 |
| 右上角 ⛶ / 再点一次 | 全屏 / 退出全屏（全窗、小窗都支持） |
| 拖顶栏（按钮以外的地方） | 挪动面板位置（只在这一会话内有效，见下）；全屏时不能拖 |
| 拖右下角斜纹拉手 | 改面板大小（全窗、小窗都支持），松手记住尺寸 |
| Esc 或面板右上角 ✕ | 关闭面板，球重新出现（全屏时 Esc 先退全屏） |
| 鼠标碰到球 | 放大到 1.15 倍 |
| 按住拖动 / 松手 | 跟手，松手后按最后 90ms 的速度带惯性滑行 |
| 擦着边缘滑过 | 不吸附，沿边惯性保留，只轻轻弹开 |
| 用力丢向边缘（垂直速度 ≥ 8） | 被那条边吸住，弹 3 次后吸死贴着 |
| 重新抓起来拖 | 解除吸附 |

### 唤起方式（三条路 + 一条快捷动作）

| 怎么唤 | 效果 |
|---|---|
| 在网页上双击球 | 打开浮动面板（默认方式） |
| **Alt + 空格** | 同一个面板：开着就收、没开就开。球进不去的地方（新标签页 / 设置页 / 内置 PDF 阅读器 / 应用商店）自动改成**开右侧栏** |
| 点工具栏图标 | 右侧栏 |
| **Alt + Q** | 把网页上**选中的文字**直接送进面板（等于点划词菜单第一颗，不带提示词）：挂成一块蓝色 chip，**不自动发送**。没选中东西时会开面板 + 提示一句，不会"按了没反应" |

快捷键在 `manifest.json` 的 `commands` 里声明（`toggle-panel` = `Alt+Space`、`ask-selection` = `Alt+Q`）。
**Chrome 不允许扩展改自己的快捷键**（安全限制），要改只能去 `chrome://extensions/shortcuts` ——
设置页里「唤起快捷键」那一块会把两条键位都列出来，也有一颗按钮直接带你过去。
要是某个键被系统或别的软件占着（Chrome 会静默不生效，不报错），去那个页面换一个就行。

### 拖到球上（小窗）

把东西拖到悬浮球上，拖动时球会放大并亮一圈蓝边，松手就弹出一个**小窗**——
尺寸是全窗的一半（宽高各 ×0.5，最小 280×305，再小控件就挤了）。

小窗里**只有**：📎 上传文件、「应用网页」、输入框、发送，外加右上角一个 ✕ 用来关。
历史记录、删除、模型下拉都收起来了。

**小窗一律开一条新对话**：不显示前面的内容，附件和「应用网页」状态也一起重置。
（双击球打开的全窗则是接着当前对话，带历史记录。）

按拖进来的东西自动分流：

| 拖进来的是 | 会变成 |
|---|---|
| 文件（图片或文本） | 直接进附件，和点 📎 选文件一样 |
| 网页上的一张图 | 进附件。图片地址是 `data:` 就直接用；是 `http(s)` 就先自己抓一份再压缩（有 `<all_urls>` 权限，不受 CORS 限制、也能带上页面的 cookie），抓不到就退回把原始链接交给接口去下 |
| 一段选中的文字 | 填进输入框，直接接着问就行 |

### 面板

- **左上角时钟图标**：历史记录抽屉，可切换、可单条删除，顶部有「新对话」和**搜索框**，
  底部有「导出 md」和「清理旧对话」两个按钮：
  - **搜索框**：输入即过滤，匹配**标题 + 每条消息的正文**（搜的是你在气泡里看到的那份文本，
    不是发给模型的原文 —— 后者塞着整页网页正文，拿它匹配会出现"我没提过这个词怎么搜出来了"）。
    搜不到会说"没有对得上「xx」的对话"，而不是给你一个空列表。选中某条或新建对话后搜索词会自动清掉
    （不清的话下次打开抽屉还是过滤后的样子，看着像"我的对话全没了"）。
    抽屉里挂着搜索词时，按 Esc 是**清空搜索**而不是关掉整个面板。
  - **导出 md**：把所有有内容的对话拼成一个 markdown 文件，存到浏览器的下载文件夹
    （文件名形如 `Nova对话-20260926-0848.md`）。正文按原样导出 —— 表格、代码块围栏都在，
    拿任何 md 阅读器打开都正常；附件只留文件名，不发全文（不然导出来是一坨没法看的）。
  - **清理旧对话**：删掉**超过 30 天没动过**的对话（`CLEAN_DAYS` 可改），
    你正在看的那个不会被删。删之前会弹面板自己的确认层，把"删几个"写清楚 ——
    想留着就先导出。
- **右上角**：¥ 查余额、⚙ 设置（API Key，没配时是橙色的）、🗑 删除当前对话（二次确认）、✕ 退出
  （侧边栏那套里 ⛶ 和 ✕ 会藏起来 —— 铺满整栏之后它们没意义）
  - **查余额**：点一下打一次 `GET https://api.deepseek.com/user/balance`（只读、不花 token），
    结果用一句提示报出来：`余额 ¥59.89（充值 ¥59.89 · 赠送 ¥0.00 → 赠送为 0 时不显示）`。
    字段名来自官方文档，2026-09-25 用真 key 实测过；没配 Key、或 Key 不对（401），提示会直接说清。
- **输入框上方那一行**：「应用网页」「这是什么？」「推荐图片」三个功能类按钮放在这儿（见下），
  底下那行留给输入相关的（附件、思考强度、模型、发送），窄面板也挤不着（放不下会自动换行）
- **底部输入框**：回车发送、Shift+回车换行、`畅所欲问` 占位
  - **↑ / ↓ 翻自己发过的话**（像终端那样）：光标在**第一行**时按 ↑，把上一条自己发的内容填回输入框；
    继续按 ↑ 一直往回翻，按 ↓ 往回走，翻过最新一条就**把你刚打的半句还回来**（不会丢）。
    翻的是**你发出去的那句**（气泡里显示的那份 `show`），不是发给模型的那份 ——
    后者塞着整页网页正文和附件全文，填回输入框就没法看了。
    光标不在第一行 / 最后一行时方向键归光标（多行改字不受影响）；发消息、换对话、新建对话后翻历史的状态归零。
  - **截图直接粘贴（Ctrl+V）**：面板里在哪儿按都行，剪贴板里的图直接进附件 ——
    不用"另存为文件 → 再从 📎 里挑"。剪贴板里**有图**才接管，纯文字一个字都不碰
    （还是浏览器原生粘贴，光标位置、换行都正常）。图片走的是和 📎 同一条管线，一样会先压缩。
  - 附件：文本类文件（代码、md、json、csv…）上限 **512KB**，内容超过 20 万字符会截断并提示；
    **图片上限 40MB，选进来后会先压缩再发**——压到最长边 1536 的 JPEG（质量 0.85），
    小 PNG（小于 2MB 字符）保留原样以保住透明通道，压缩后反而更大的话也用原图。
    之所以敢压这么狠：官方文档写明图片送进去之前本来就会被缩放到"总共约 1300×1300 像素"，
    每张最多算 1024 token，本地先压**模型看到的东西完全一样**，只是省了上传体积和请求体。
    实测一张 3000×2000 的 PNG（data URL 约 835 万字符）压完剩 2.9 万字符，约 0.4%。
  - **图片附件双击可以预览**：图片类附件在 chip 上带一张 20×20 缩略图，**双击**就在面板里铺开看
    （带文件名 + 体积；点画面或按 Esc 关掉，Esc 只关预览、不会把面板一起关了）。
    **只对"这次待发的附件"有效** —— 发出去之后 base64 不落库（存进 storage 会撑爆配额），
    所以历史消息里没有图可看，这不是 bug。
  - **「这是什么？」快捷提示词**（输入框上方那一行的右边）：点一下把这句填进输入框，再点一下收回去。
    输入框里已经有字的话是**追加**（另起一行），不会覆盖你写的东西；点击后按钮会高亮。
    文字在 `config.js` 的 `imagePrompt` 里改（留空字符串则不显示这个按钮）。
    另外 `config.js` 里还有 `autoFillImagePrompt`（默认 `false`）——改成 `true` 就变成
    **图片一进附件自动填**，不用点按钮。两种可以同时用。
  - **推荐图片**（同一行的最右边，默认关）：**点一下开 / 关**，开着时按钮高亮。
    开启后每轮回答的末尾会多一行「配图」，里面是几个**能搜到相关配图的词**，
    点一下就开着新标签页去搜图（用哪个搜索引擎在 `config.js` 的 `imageSearch` 里改）。

    | 你看到的 | 说明 |
    |---|---|
    | 回答下面那行 `配图 [HTTP 缓存 流程图] [浏览器缓存 304 示意图]` | 词是模型按这轮回答现想的，2~3 个 |
    | 点某个词 | 新标签页里搜这个关键词的图片（右键还能"复制链接"） |

    - **为什么给的是"搜索词"而不是图片**：扩展自己不能生成图片，接口也不会返回图片；
      而让模型直接给图片网址，它**必然会编**，点了就是 404。搜索词是唯一真能用起来的东西。
    - 那段标记（`<img-reco>…</img-reco>`）只给程序看：正文里看不到它，**点「复制」拿到的东西里也没有**，
      发给模型的历史里同样剥掉了（留着会变成"示范"，关掉开关后模型还照样写）。
    - 模型某轮没给词，那一行就**不显示** —— 不硬凑一行空的。
    - 开关存在浏览器里：刷新页面、换个标签页、重开面板都还是开着的。想关掉再点一下。
  - **应用网页**（同一行的左边）：**点一下循环切换三种状态**，按钮上的字会跟着变：

    | 按钮文字 | 状态 | 每次提问带上什么 |
    |---|---|---|
    | `应用网页` | 关 | —— |
    | `整页` | 整页模式 | 整页正文（含未滚动到的部分）+ 页面里的图片 |
    | `可见区` | 可见区模式 | 屏幕里实际显示的文字 + **一张当前屏幕的截图** |

    状态也会显示成输入框上方一枚 chip（`整页：标题 · N 图` / `可见区：标题 · 1 图`），点 chip 上的 × 直接关。
    两种模式都是**发送那一刻**才抓，页面翻页、刷新、加载出新内容都跟得上。
    整页模式：正文上限 60000 字（超出截断），图片最多 8 张，`<main>` 优先、没有就合并所有 `<article>`；
    可见区模式：文字只截视口内的（最多 600 条），外加一张截图。
  - **正文增量缓存（省 token）**：同一页连着问好几轮时，正文**只在第一轮发全文**，后面几轮只发一行
    「正文和上面那条完全相同」。原来的做法是每问一句就把整页重发一遍 —— 一篇 2 万字的文章问 5 句，
    光正文就要发 10 万字 ≈ 10 万 token。
    - 只在**能证明"这次请求里已经有那份正文"**时才省：命中条件是同 `url` + 同指纹，
      且那条消息落在最近 `KEEP_RECENT`（12）条之内 —— 这几十条是无条件保留的，必然出现在本次请求里。
      掉出窗口就老实重发全文（宁可多花 token，也不能让模型手里没有正文）。
    - **页面改了 → 一定重发全文**（并带上最新内容），不会拿旧内容糊弄模型。图片列表也在指纹里。
    - 指纹不落库（重开浏览器后第一次一定重发全文）。省下时 chip 上会写「正文已缓存」，
      并提示一句省了多少字。可见区模式的**截图每轮照拍照发** —— 截图每轮都是新的，那才是它的意义。
  - **附件正文也有增量缓存**（2026-10-13 补）。上面那套只解决"同一页连着问"，而**附件比正文更贵**
    —— 单个文本附件上限 20 万字符（网页正文才 6 万），却一直没做去重：拖一份长文档追问 5 轮，
    那 20 万字原来要原样发 5 遍。
    - 命中的判定和网页正文一模一样：同一份内容（`文件名 + 长度 + 内容哈希`）在最近
      `KEEP_RECENT`（12）条里出现过 → 这轮只发一行「内容和上面那条完全相同」。
    - **换了一份附件就一定重发全文**（名字、长度、哈希只要有一处不同就算另一份），不会拿旧的糊弄模型。
    - 指纹同样不落库（附件里的图只活在内存里，重开浏览器后老图回不来，那时候必须老实重发）。
    - 附件和网页**同时命中就合成一句提示**，不会连着弹两条。
  - 下拉框选模型：**显示名和真实 model id 分开**，id 以官方文档为准
    （<https://api-docs.deepseek.com/quick_start/pricing>）：

    | 显示 | 发给接口的 model | 能看图 |
    |---|---|---|
    | V4.1 Flash | `deepseek-flash` | ✅ |
    | V4 Pro | `deepseek-v4-pro` | ❌ |
    | V4 Flash | `deepseek-v4-flash`（旧名，官方仍接受，实际由 V4.1-Flash 服务） | ✅ |

    加模型就在 `config.js` 的 `models` 里加一条 `{ label: '显示名', id: '接口认的 id', vision: true }`，
    也可以只写字符串（显示名即 id，默认按能看图处理）。`vision` 为 false 的模型收到图片时，
    代码会把图片换成"图片清单"文本（只留地址），并提示你一句，不会发出去让接口报 400。
    两个模型都支持思考模式，思考过程折叠在气泡上方的「思考过程」里。
  - 旁边那个**思考强度**下拉，四档，发请求时带两个字段：

    | 显示 | 真正发给接口的 | 什么时候用 |
    |---|---|---|
    | 不思考 | `thinking:{type:'disabled'}` | 翻译、改错字、格式化这种，要的就是快 |
    | 思考·低 | `reasoning_effort:'low'` | 日常问答 |
    | 思考·高 | `reasoning_effort:'high'` | 默认这档；数学题、写代码 |
    | 思考·最强 | `reasoning_effort:'max'` | 绕的推理、硬骨头 |

    ⚠ 这里踩过两个坑（2026-10 照官方文档纠正过，改之前是错的）：
    - 「不思考」**不能**靠发 `reasoning_effort: 'none'` —— 官方只认 `low`/`high`/`max`，
      这个值不在合法列表里，会被**静默忽略**：模型照旧思考，钱照花、还慢，而且从外面完全看不出来。
      真正的关法是 `thinking: {type: 'disabled'}`（关掉时也不再发 `reasoning_effort`）。
    - 官方映射表里 `medium` 会被**归到 `high`** —— 所以原来那个「思考·中」其实一直跑的是「思考·高」，
      名字骗人，已经删掉。老配置里存过 `medium` 的，打开面板时会自动迁移成 `high`，行为一点不变。
    - 另外 thinking 是**默认开着**的：什么都不传 = 默认 high，不等于"不思考"。
    档位列表在 `config.js` 的 `efforts` 里，删掉不想要的整行就行；选中的那档存在
    `chrome.storage.local`，下次打开还是它。
  - 每条回答底下会跟一行**这一轮的实际用量**，鼠标悬停看精确数字：

    ```
    输入 1.2k · 命中 1.1k · 输出 340 · 思考 200
    ```

    数据来自接口返回的 `usage`（请求里带了 `stream_options.include_usage` —— 流式下 usage
    只在**最后一块**里给，不主动要就没有）。凭什么值得看：
    - **缓存命中的输入价是未命中的 1/50**（$0.003 vs $0.15 每百万 token），所以"命中"那项
      就是省钱的关键数；
    - **"思考"那项是"关思考到底有没有生效"的判据** —— 档位选「不思考」时它应该是 0，
      不是 0 就说明参数没被服务端认（就是上面那个坑）。
  - **每条消息底下还有一行时间**（`21:36`，鼠标悬停看完整日期时间）。当天只显示时分，
    不是当天显示"月/日"。2026-10-13 之前存下来的老记录没有这个字段，**那就不显示** ——
    不拿"现在"糊一个假时间。
  - 蓝色圆钮：发送；生成中变成停止按钮，可以中断
- 回复是流式吐字的，**markdown 会正常渲染**：表格、标题、有序/无序列表（含嵌套）、引用、
  分隔线、代码块、行内代码、加粗、斜体、删除线、链接。模型答出来的表格长这样
  `| 项 | 内容 |` + `|---|---|`，只转义不解析的话会原样显示成一串竖线——所以才需要这套解析
  （`mdToHtml()`，够用即可，不追求完整 CommonMark）。见 `docs/panel-format.png`。
- **图片只在你发送的那一轮有效**：base64 存进 `chrome.storage` 会撑爆配额，所以图片不进历史，
  下一轮就只剩文字。对话气泡里会留一个文件名 chip，提醒你那轮带过图。
  - 但**同一次会话里**（面板没关、页面没刷），最近带过图的那几条消息仍然会把图一起发出去 ——
    连着看图追问时模型不会"瞎"。只保留最近 `MAX_CTX_IMAGES`（默认 3）条：
    官方一张图最多算 1024 token，钱不多，可一张图压完也是几万字符的 data URL，
    每轮都重发一遍纯粹在撑大请求体、拖慢上传。
- 历史记录存在 `chrome.storage.local`，换页面、重开浏览器都还在
  - 默认配额 **10MB**，聊得久了会撞上（撞上就写不进去）。所以历史抽屉底部有「导出 md」和「清理旧对话」。
- **多窗口 / 多标签页是通的**：面板可以同时在两个地方开着（两个标签页，或者网页浮窗 + 侧边栏），
  两边看到的是同一份对话：
  - 一条消息发出去（吐字期间也会同步进度），另一个窗口**当场**多出来这一条，不用刷新
  - 新建 / 改标题 / 删除对话，另一边跟着变
  - 两边写盘时会**按对话 + 按消息合并**，不会互相盖掉；**同时往同一个对话里打字，两边的消息都留得住**
    （消息有身份 `mid`，靠它去重）
  - 删掉「正在看的那条」时不会停在一个已经不存在的对话上，会自动换一条
  > 「回到某条之前」是**故意**删掉后面那几轮，这一点会随对话一起记住（`cutAt`），
  > 所以别的窗口手里那份旧的长版本也不会把它救回来。

### 工具栏图标 → 侧边栏

**为什么要有这个入口**：球是贴在网页上的，所以「新标签页」「设置页」「内置 PDF 阅读器」这些地方它永远进不去
—— Chrome 不允许扩展注入 `chrome://` 页面，加什么权限都没用。想让这些地方也能聊，只能换入口。

点工具栏上那颗球图标 → **浏览器右侧开一条栏**，里面就是同一个面板：

- **同一份代码**：侧边栏那页（`sidepanel.html`）直接引 `config.js` + `panel.js` 来跑，不是另做一份界面。
  历史记录、模型选择、思考强度全部共用（都走 `chrome.storage`）。
- **切标签页不关**，宽度可以用鼠标拖。
- **自动铺满**：面板在侧边栏里会铺满整栏、去掉圆角和阴影 —— 那儿没有"浮在网页上"这回事。
- **藏掉两个按钮**：「全屏 ⛶」铺满之后没意义；「退出 ✕」只会退出一片空白（关侧栏该用浏览器自己的按钮）。
  Esc 也一样，不关面板。
- **「应用网页」能正常用，而且读的是你正在看的那张标签页**：侧栏没法读网页的 DOM
  （它自己的 `document` 就是侧栏本身），所以点它会通过消息去问当前标签页 ——
  而网页上跑的是**同一份 `panel.js`**，手里已经有提取函数，直接回给它就行。
  「整页」和「可见区」两种模式都成立（截图那条本来就只截标签页，天然是对的）。
  碰不到的页面（新标签页、设置页、PDF 阅读器）会明确提示"这个页面读不了"，不会假装成功。
- 球**不在**侧边栏里 —— 球仍然是网页上的东西，两边互不干扰。

**想改成"点图标弹小窗"**（Popup）：manifest 里给 `action` 加 `"default_popup": "sidepanel.html"`，
再把 `background.js` 里那句 `setPanelBehavior` 删掉就行。代价是小窗**点到别处就关**，
要边看网页边聊会很别扭 —— 这也是选侧栏的原因。

### 复制、划词提问、回到某条之前、重试

- **回到某条之前（最小版的"回滚"）**：鼠标移到任意一条**你的**提问上，右上角出现「回到这里」。
  点一下先弹一层确认（写清"会丢掉这条和后面共 N 条、约 M 字""带过附件/图片的图片不会回来"
  "输入框里现在的字会被换掉"），确认后：**截断到这条之前 + 这条的文字放回输入框**，改完就能发。
  - 这就是"反复试提示词"真正要用的动作：不用手打两遍，也不会顺手把好答案删了找不回来。
  - **没有"快照"这个实体**：消息数组本来就是 append-only 的，回滚 = 保留前 N 条，
    所以"快照"就是那个下标——零存储，也不会和主数据不同步。
  - **代价说清楚**（确认层里就有）：不可撤销、图片回不来（base64 不落库）、token 也不回滚
    （重试就是再花一次钱）。
  - 确认层是**面板自己画的**（`askConfirm()`），不用 `window.confirm`：content script 里那个是
    页面的 `confirm`，页面能改写它（改写后永远返回 true），拿它给不可逆操作把关不可靠
    —— 所以**所有不可逆操作都走这一层**：回滚、删对话（工具栏和抽屉里那两处原来用的是
    `window.confirm`，2026-09-26 统一换掉了）、清理旧对话。
  - 回滚会把后面所有内容一起丢掉，包括那些"正文和上面那条完全相同"的标记 —— 否则模型会去
    上面找一条已经不存在的消息（自检里专门断言了这条）。
- **重试某条回答**：鼠标移到任意一条 AI 回答上，右上角除了「复制」还多一个「重试」。
  点一下用**同样的上文**重新生成这条 —— 问题原样留着，只把这条回答换成新的。
  - 和「回到这里」的分工要分清：那个是改**问题**（文字放回输入框、消息删掉），
    这个是换**答案**（什么都不用重打）。看完一段回答觉得"不对味"时，这是最顺手的动作。
  - **它后面的内容会被一起丢掉**（只重生成中间某一条会让后面几轮凭空接不上），
    所以后面还有消息时会先弹确认层；是最后一条就直接重来，不问。
  - 重打一次接口、也**再花一次钱** —— 界面上那句提示和确认层里都写了。
  - 实现上：`send()` 里"建请求 → 吐字重绘 → 收尾 → 同步"那一段抽成了 `runAnswer(am)`，
    两条路共用；重试只负责"把消息和 DOM 一起截断到这条之前"，然后接上同一个 `runAnswer`。
    DOM 侧是**从后往前删**到第 idx 行，不走 `renderAll()` —— 后者会把前面每一条都重跑一遍
    markdown 渲染，长对话里那是几十毫秒的顿挫。
- **复制整条回答**：鼠标移到任意一条 AI 回答上，右上角会出现「复制」。点一下，整条回答进剪贴板，
  格式是**人能直接读的纯文本**（`mdToText()` 转换）：表格去掉 `|---|` 那行、**按列对齐**
  （中文按两个显示宽度算，所以在等宽字体里才齐），去掉 `**`、`#`、反引号、`>` 这些记号；
  列表的 `-` 和 `1.` 保留（那是结构，不是记号）；链接留成 `文字 (网址)`；代码块去掉围栏。
  为什么不复制屏幕上那份渲染结果：复制 HTML 粘到别处，代码缩进会全乱。
- **复制代码块**：每段代码自己的右上角也有一个「复制」，只复制那段代码（连围栏都没有）。
- **划词快捷动作**：在网页上选中一段文字，选区上方冒出一行小动作。
  不想点菜单也行：**按 `Alt + Q`** 直接把选中的文字挂进面板（等于点第一颗「问 X」）。

  | 按钮 | 点下去挂上的 chip（发送时才拼进消息） |
  |---|---|
  | `问 Nova` | `问 Nova · N 字` —— 不加提示词，自己想怎么问就怎么问 |
  | `翻译` | `翻译 · N 字` + 提示词「把下面这段翻译成中文（已经是中文就译成英文），只给译文，不要解释：」 |
  | `总结` | `总结 · N 字` + 「用几句中文总结下面这段的要点，先说结论：」 |
  | `解释代码` | `解释代码 · N 字` + 「解释下面这段代码在做什么，并指出可能有问题的地方：」 |
  | `改写` | `改写 · N 字` + 「把下面这段改写得更通顺自然，保持原意、长度相近：」 |
  | `提取要点` | `提取要点 · N 字` + 「把下面这段的要点列成条目，每条一行：」 |

  - 点完**面板的 chips 区多一块蓝色小块**（和附件一样的样子，点 × 撤掉），**输入框保持干净**——
    选一段长文也不会把输入框糊满，你还能自己补一句"只翻第一段"。
  - **发送那一刻才拼进消息**：你打的字在前，然后是「提示词 + 围栏包住的选段」
    （围栏是让模型分得清"哪句是要求、哪段是材料"）。**不会自动发送**。
  - 同一段文字 + 同一个动作点两次**不会重复挂**（会提示"这段已经在下面了"）；
    选段超过 8000 字会截断并提示。
  - 动作列表在 `config.js` 的 `selectionActions` 里（`label` 是按钮上的字，`prompt` 是提示词）：
    不想要的整行删掉，留空数组就只剩「问 Nova」那一颗。也允许只写字符串（当按钮文字、不带提示词）。
  - 在面板自己的输入框里选字**不会**弹这行菜单（那里是编辑，不是提问）。
  - 菜单自带深色底 + 白字：网页有深有浅，跟着网页配色必然有一半看不清。
- **聊得太长时会自动收口**：历史超过约 30 万字符（`MAX_CTX_CHARS`）才只带最近的一部分，
  发送时会提示"前面 N 条这次省略了"。最近 12 条（`KEEP_RECENT`）任何时候都带上。
  ⚠ **这个阈值不能随便往小调**：模型上下文上限其实是 **1M token**（30 万字符≈20 万 token，
  还留着 4 倍余量）；更要命的是——从**头部**丢消息会让请求前缀整体错位，导致**后面全部跳过缓存**
  （命中 $0.003/M、未命中 $0.15/M，差 50 倍）。以前那个 8 万字符，看着像在"省 token"，
  其实把缓存打碎了、反而更贵 —— 这就是它被改大的原因。
  - **收口的位置按 8 条一档取整**（`CTX_CHUNK`），不是"刚好压回线下"。
    这是 2026-10-13 修的一个**持续性**问题：原来算法是"超了就从头部丢到刚好不超"，
    于是对话一旦越过阈值，**每一轮都得再往前丢一点**（每轮都会新增长度），
    起始下标每轮都在动 → 请求前缀每轮都在变 → **缓存从那一刻起永久 0 命中**，
    整段历史全按未命中价结算。砍历史省下的那点 token，远不如把缓存打碎亏得多。
  - 取整之后，每轮下标只挪一两条，**连续好几轮落在同一档** —— 这几轮的请求层层嵌套
    （上一轮的整个请求就是这一轮的前缀），缓存整段命中；只有跨档那一轮要重来。
    代价是取整会多丢几条历史（最多 7 条），明码标价，完全值。
  - 这段逻辑抽成了纯函数 `ctxWindow(msgs, budget, keepRecent, chunk)`，
    离线单测直接抠它跑（`docs/test-render.js` 第 7 节，9 条断言）。

### 出错的时候它说什么

失败时不会把原始报错甩给你，而是翻译成**人话 + 下一步做什么**（`friendlyErr()`）。原来那句
`出错了：Failed to fetch` 唯一的信息是"坏了"，不知道该点哪儿。现在认识的几种：

| 触发情况 | 气泡里会写 |
|---|---|
| 请求压根没发出去（`Failed to fetch` 一类） | 「连不上 api.deepseek.com（请求没发出去）。开着代理（Clash 之类）的话，先把它关掉、或者给 deepseek.com 加一条直连规则，然后再点「重试」；也可能是网断了。」 |
| `401` | 「API Key 不对或已经失效 —— 点右上角 ⚙ 打开设置页，填一把新的（改完立刻生效，不用刷新）。」 |
| `402` | 「账户余额不够了 —— 点面板顶上的钱包图标看一眼余额，充值后再点「重试」。」 |
| `429` | 「请求太频繁，被限流了 —— 等十几秒再点「重试」就好。」 |
| `400` | 「请求被拒（400）。最常见的原因是上下文太长 —— 新开一条对话再问，或者把附件/网页正文去掉再试。」 |
| `5xx` | 「DeepSeek 服务端出问题了（HTTP xxx）—— 这不是你的配置问题，过几分钟再点「重试」。」 |
| 你按了停止 | 「（已停止）」—— 这个不算失败，不提"重试" |
| 一个字都没吐出来 | 界面上写「（没有返回内容）」，**并且**提示可以重试（原来是干瞪眼） |

- 翻译认不出来时，**原始报错一定附在末尾** —— 翻译错了的时候，原文是唯一的线索。
- 失败会**额外弹一个提示**（"原因在那个气泡里，点重试可以再来一次"）：用户可能正滚在别处，
  只写在气泡里他看不到。
- 每次失败的气泡右上角本来就有「重试」，所以"报错 → 再来一次"是原地一步，不用重打问题。
- 状态码是 `callAPI()` 抛错时挂上去的（`err.status`），文案统一在 `friendlyErr()` 里 ——
  **别把提示文案散回 `callAPI`**：那里看不见网络层错误和 AbortError，散在两处会互相打架。

### 全屏、拖动与拉角缩放

两个面板（双击打开的全窗、拖进小窗）都有这几样：

- **全屏**：右上角 ⛶ 按钮（⚙ 右边、🗑 左边）。点一下铺满整个视口，圆角、边框、阴影都去掉，
  按钮图标变成"收起"的样式；再点一下回到原来的大小和位置。
  Esc 在这个状态下**先退全屏**，再按一次才关面板——不然一按就全没了，容易误伤。
  关面板时若还在全屏，下次打开会回到普通大小（不会莫名其妙又是全屏）。
- **顶部拖动**：按住顶栏（历史 / ⚙ / 全屏 / 删除 / 退出那几个按钮**以外**的地方，中间那块标题也算）
  就能把面板挪到任意位置。光标在顶栏上是 `move`，按钮上还是正常的手型。
  全屏状态下不能拖（也没地方拖）。
- **拉角缩放**：右下角那个斜纹小三角就是拉手，按住往右下拖变大、往左上拖变小。
  - 最小值：全窗 300×320、小窗 240×240（再小工具条上的按钮就挤成一团了）
  - 已经贴到屏幕右边/下边还想继续长大时，整个面板会**往左上让位**，让你拖着的那个角跟手；
    反过来缩小就自己回到原位
  - 拖动和缩放都不会跑出屏幕（自动夹在视口内），窗口尺寸变化时也会重新夹回可视区
- **大小记得住，位置不记**：拉角松手会把尺寸存进 `chrome.storage.local`（`__ds_size__`，
  格式 `{ full:{w,h}, mini:{w,h} }`，全窗和小窗各记各的），下次打开还用这套；
  想回到默认大小就删掉这个键。**位置每次打开都按球重算** —— 面板是"跟着球出现"的，
  球挪到哪儿它就在哪儿冒出来。以前是把位置也记下来，结果只要拖过一次，面板就永远钉在
  那个旧位置、球挪到哪儿都不跟（看着就是"窗口和球对不上"），所以 3.5 之后不记位置了。
  拖顶栏仍然能挪，只是仅限当下这一会话。

改尺寸和位置只影响几何，**不影响显示哪些控件**：小窗全屏之后依然是小窗那套（历史、删除、
模型下拉仍然收起）。如果你希望小窗一全屏就变成完整体验，说一声，加一行判断的事。

### 「应用网页」到底读到了什么

两种模式的取材完全不同，这是它们的核心区别：

| 内容 | 整页模式 | 可见区模式 |
|---|---|---|
| 屏幕内的文字 | ✅ | ✅（只取视口内的） |
| 往下滚动才看得到的文字 | ✅ | ❌ |
| 当前屏幕的截图 | ❌ | ✅（一张 JPEG） |
| 页面里的图片 | ✅ 最多 8 张 | ❌（截图里能看到什么就是什么） |

两边的边界：

| 内容 | 情况 |
|---|---|
| 被 CSS 隐藏的文字（折叠区、SEO 文本、移动端专用菜单） | 整页模式会带上（克隆节点后取文本，语义等同 `textContent`）；可见区模式不会（靠位置框判断，`display:none` 的元素框为 0，自然排除） |
| 已解码、且 ≥120px 的图片 | 整页模式收，最多 8 张，小于 120px 的图标和 1×1 埋点过滤掉 |
| 懒加载还没加载出来的图 / 加载失败的图 | ❌ 跳过（`naturalWidth` 为 0，收了也只是占位图） |
| `<iframe>` 里的内容 | ❌ 拿不到（截图里能看到，但读不出文字） |
| Shadow DOM 里的内容（部分 Web Component 站点） | ❌ 拿不到（同上） |
| `<canvas>` 画的、图片里印的文字 | ❌ 除非进了截图或那张图本身被发出去 |
| CSS `::before` / `::after` 生成的内容 | ❌ 不在 DOM 文本里 |

**可见区模式的三点实情**：

- 屏幕里的文字是**按元素剪枝**取的：某个元素的位置框整个在视口外，它这一支就不再往下翻。
  老写法是逐个文本节点都拿父元素量一次位置框 —— 一个 3 万节点的页面（微博/知乎首页那种）
  要量 2.6 万次，实测约 46ms，点「引用当前网页」会明显顿一下；剪枝后是 2000 次 / 约 3ms。
  **代价**：`position:fixed` 的元件（吸顶导航、浮动客服、回到顶部）的可见性不取决于祖先，
  祖先容器滚出视口时它会跟着被剪掉 —— 那几个字（"在线客服"这种）就带不上了，正文不受影响。
- 截图必须由后台脚本调 `chrome.tabs.captureVisibleTab`，content script 自己调不了，
  所以有了 `background.js`。这也意味着 `manifest.json` 需要 `<all_urls>` 主机权限
  （官方文档：调用该方法需要 `<all_urls>` 或 `activeTab`）。
- 截图前会**先把面板收起来**（否则会把对话面板自己拍进去），你会看到它闪一下；截完立刻恢复。
  Chrome 限制这个方法**每秒最多调 2 次**，连着发得太快会失败并提示你。

## 参数

悬浮球（`content.js` 顶部）：

| 变量 | 默认 | 含义 |
|---|---|---|
| `SIZE` | 53 | 球直径（px） |
| `TOUCH_SCALE` / `TOUCH_MS` | 1.15 / 140 | 鼠标碰到时的放大与时长 |
| `FRICTION` / `MAX_SPEED` | 0.90 / 45 | 惯性衰减与速度上限 |
| `BOUNCE` / `CAPTURE_SPEED` | 0.45 / 8 | 撞边缘的反弹与"算被丢过去"的门槛 |
| `MAX_BOUNCES` / `EDGE_PULL` | 3 / 0.35 | 吸住后弹几次吸死、朝边缘的拉力 |
| `DBL_TAP_MS` | 500 | 两次**轻点**间隔小于它算双击（Windows 默认双击间隔就是 500ms） |

> 双击只认"轻点"：某一次按下后移动超过 4px 就算拖动，拖动不会参与双击判定，
> 所以快速连拖两下不会被误判成双击。系统双击速度调得很慢的话，把 `DBL_TAP_MS` 再调大。

面板（`panel.js` 里 `computeRect()`）：

```js
var w = clamp(Math.round(W / 3), 360, 560);   // 宽：屏幕的 1/3，360–560 之间
var h = clamp(Math.round(H * 0.62), 420, 860); // 高：屏幕的 62%
```

### 面板里的其它常量（`panel.js` 顶部）

| 变量 | 默认 | 含义 |
|---|---|---|
| `MAX_CTX_CHARS` | 300000 | 发给模型的历史预算（字符）。上限其实是 **1M token**（≈150 万中文字符）；**调小会让前缀错位、缓存全失效，反而更贵** —— 详见上面「聊得太长时会自动收口」 |
| `CTX_CHUNK` | 8 | 超预算时"从第几条开始带"要**按它取整**。取整是为了让连续几轮落在同一档 → 请求前缀不变 → 缓存整段命中。**调大** = 更稳但一次多丢几条；**调成 1** = 回到"每轮丢一点、前缀永久错位"的老毛病 |
| `KEEP_RECENT` | 12 | 无论历史多长，最近这么多条一定带上（否则连"你刚才说的是哪个"都答不了）。**网页正文和附件的增量缓存也只看这 12 条**——它们必然在本次请求里，所以命中就一定安全 |
| `MAX_TEXT_SENT` | 200000 | 单个文本附件真正发出去的上限，超出截断 |
| `MAX_PAGE` | 60000 | 「应用网页」抓正文的上限，超出截断 |
| `MAX_CTX_IMAGES` | 3 | 历史里**还带图**的消息条数上限。官方的图按每张 1024 token 封顶算，但 data URL 几万字符，每轮重发会撑大请求体 |
| `CLEAN_DAYS` | 30 | 「清理旧对话」删掉多少天没动过的对话（正在看的那个不删） |

## 实现上的注意点

- **面板不用 iframe，直接建在页面的 Shadow DOM 里**。原因：严格 CSP 的网站（GitHub 这类）会把 `chrome-extension://` 的 iframe 拦掉，面板根本打不开。代价是面板里的键盘/滚轮事件要手动 `stopPropagation`，否则会被网页的快捷键吃掉。
- **双击必须自己判定，不能挂 `dblclick`**。球的 `pointerdown` 里调了 `preventDefault()`，而规范规定这会抑制 `click` / `dblclick` 这类兼容鼠标事件，挂监听永远不会触发。现在用两次 `pointerdown` 的时间间隔（`DBL_TAP_MS`）判定。
- **请求从 content script 发出**，需要 `host_permissions` 里的 `https://api.deepseek.com/*`，否则会被 CORS 拦掉。
- **存历史前要剥掉 DOM 引用**：渲染时把 `$body` / `$think` 挂在消息对象上，`chrome.storage` 序列化不了 DOM 节点，所以 `plainChats()` 先拍一份纯数据快照再存。
- **图标是内联 SVG**：严格 CSP 的网站会拦掉 `chrome-extension://` 资源请求，路径直接写进 js。
- **速度采样窗口**：只取松手前 90ms，`while (i > 0 && now - samples[i - 1].t < 90) i--` 里的 `i - 1` 不能省。
- **碰撞要分轴判定**：球停在边缘上时坐标恒等于边界，只判断"越界"会把沿边滑行当成每帧撞墙。
- **跨 shadow 判断事件来源要用 `composedPath()`，不能看 `e.target`**。球和面板都在 Shadow DOM 里，
  事件冒到 `document` 时 `e.target` 会被**重定向成宿主元素**（`__ds_float_ball__`），
  里面真正的元素看不到。划词菜单就栽在这儿：原来写 `e.target === selBtn` 永远为假，
  一按下就被自己的 `hideSel()` 藏掉 → mouseup 落空、click 不触发，表现是"看得见菜单但点不动"。
  后来菜单从"一颗按钮"变成"一行按钮"（`isSelBar`），判断改成了
  `composedPath().indexOf(selBar) >= 0` —— **要覆盖整棵子树**，只比 container 自己会漏掉里面的按钮。
- **body 渲染要按"块"解析，不能只把换行换成 `<br>`**。模型答的都是标准 markdown，
  只做行内替换的话表格、标题、列表全都会以原文露出来。`mdToHtml()` 先把 ``` 切出代码块，
  剩下的交给 `mdBlocks()` 按行扫：表格（下一行是分隔行才算，否则单独一行 `---` 会被误判）→
  标题 → 分隔线 → 引用 → 列表 → 普通段落。列表还处理了"续行"（缩进比当前层深就接着上一项写），
  否则一行普通文字会把有序列表截成两段、编号从 1 重新数。
- **面板要能跑在两种"宿主"里**（网页上的浮窗 / 浏览器侧边栏），靠的是 `window.__DS_HOST` 这个标记：
  承载它的页面在 `open()` 之前设上，面板就铺满容器、并藏掉两个在那个环境下没意义的按钮（`isHost()`）。
  **必须是函数、不能是顶部常量** —— 侧边栏那页是在 panel.js 之后才加载的，设标记得来得及。
- **"读网页"在两种宿主里走同一个函数**（`grabContext()`）：网页上读自己这一页，
  侧栏里发 `{type:'ds-grab-page'}` 去问当前标签页（`tabs.query` + `tabs.sendMessage`）。
  **两边返回同一个形状**，所以发送流程不用分情况写。网页侧那半是 panel.js 自己注册的监听 ——
  所以侧栏里**不能**注册（否则它会应答自己），这条在自检里专门断言了。
  改这一对的时候，两边的字段名要对齐（`ok / title / url / text / images / visible / cut`）。
- **粘贴（`onPaste`）挂在自己的 shadow root 上，不是挂在 textarea 上**：焦点点过回答、点过 chip
  之后会跑掉，挂在输入框上那种时候就失灵了。判断"要不要接管"只看**剪贴板里有没有图**
  （`dt.files` / `dt.items` 里 kind=file 的 image/*）：有图才 `preventDefault()`，
  否则一律返回、让浏览器原生粘贴 —— 自己实现文字插入迟早会在换行、光标位置上翻车。
  另外剪贴板里的位图**没有文件名**，得 `new File([blob], '粘贴的图片.png', ...)` 包一层，
  不然附件 chip 上会显示成 `undefined`。
- **图片预览用"面板里盖一层"，不是新开标签页**：`data:` URL 在 `window.open` / `tabs.create`
  里都会被 Chrome 拦掉，所以只能自己盖。关掉时要用 `img.removeAttribute('src')` 来松开那份
  base64 —— 写 `img.src = ''` 是错的：空字符串会被当成相对路径解析成**当前页面地址**，
  浏览器顺手又去加载一次页面，图也没真松开（自检里专门断言了这条）。
- **网页正文的增量缓存**（`hashText()` + `pageBlockInWindow()` + `msg.pageKey`）。判断"要不要重发正文"
  的**唯一**依据是"这次请求里是不是已经有它了"，实现上是查最近 `KEEP_RECENT` 条里有没有同 url+同指纹的消息。
  这条边界不能放宽到"上次发送时带过"——历史窗口会把中间的消息挤掉，那样就会**静静地丢掉上下文**
  （模型看不到正文却以为看得到）。指纹用 `msg.pageKey` 挂在消息上、**不落库**：重开浏览器后一定重发一次。
  改这块的时候，自检里那三条（首轮带全文 / 页没变不重复 / 页变了重发）都要保持绿。
  写断言时注意：不能断言"请求里没有正文"——上一轮的消息就在历史里，正文当然还在；
  要断言**出现次数**（复用成功 = 1 次，没复用 = 2 次）。
- **多窗口同步**：写盘前"读回来合并"，收到变化就**就地**并进内存
  （`mergeChats()` / `mergedMessages()` / `saveChatsMerged()` / `adoptFromStorage()`）。
  原来 `persist()` 是把内存里那一整套 chats 整份覆盖写 —— 两个标签页各有一份内存，后写的把先写的
  **整份盖掉**，表现就是对话静默消失。现在的规则：按对话 id 合并，**消息按 `mid` 认身份取并集**；
  同一条消息两边都有时取**更完整**的那份（流式写到一半的版本 vs 最终版，靠这个挑对）。
  标题沿用"后动过的那份"，但别被"新对话"这个默认名顶掉。
  **四个坑**：
  ① 合并会把"存储里还有、这边没有"的对话当成本窗口新建的收回来 ——
     所以**删对话要记进 `state.dead` 名单**（`dropChat()`），不然删完下次写盘又活了；
  ② 收到别的窗口的写入时要把"存储里已经没有、但这边**见过**（`state.seen`）的"也删掉 ——
     用 `seen` 判而不是"全都删"，本窗口刚建、还没写过的空对话才不会被误删；
     正在看的那条被别处删了就自动换一条（以前是"正在看的那个不动"，结果留一条幽灵、下次写盘还把它复活）；
  ③ **并集不能把"故意删掉的"救回来**：「回到某条之前」会留下 `cutAt`（保留到哪一条的 key），
     合并时按它裁掉**对方**那份的旧尾巴；而且**双方标记一致就不裁** ——
     否则截断完之后新加的消息会被当成旧尾巴，锚点后面永远长不出新内容（这个坑是自检抓出来的）；
  ④ 吐字期间**不能动当前对话的消息数组** —— `send()` 手里攥着那个流式气泡的对象引用，
     换掉之后它后面写进去的字就没人看得见了。所以收到变化先记 `state.syncPending`，
     等这一轮结束（或下次写完盘）再对齐。
- **唤起快捷键是"后台转发"的一条路**：`chrome.commands.onCommand`（background.js）→ 给当前标签页发
  `ds-toggle-panel` → 页面里的面板自己开合（`toggle()` 早就有）。页面里没人接（`chrome://`、内置 PDF、
  应用商店这些注不进内容脚本的地方）就退到 `chrome.sidePanel.open()` —— 跟点工具栏图标同一条路。
  第二条 `ask-selection`（`Alt+Q`）同样转发（`ds-ask-selection`），但**故意没有兜底**：那些注不进内容
  脚本的地方本来也选不到网页文字，静默不动才是对的。它的处理写在 **content.js** 里 —— 那边有
  `selText() / selCache / runSelAction()`，直接复用；**别在 panel.js 里再撸一遍读选区**，两份迟早不一致。
  没选中时不静默：把面板叫出来 + 一句提示（靠新交出去的 `__dsPanel.toast`）。
  **`chrome.commands` 只能读不能写**：扩展改不了自己的快捷键，所以设置页那块只能"显示当前键位 +
  一个去 `chrome://extensions/shortcuts` 的入口"，别做成下拉框（做不到）。
  老浏览器没有 `chrome.commands` 时（自检页也是），`readShortcut()` 返回 `null` 而不是 `''` ——
  "读不到"和"没设置"要说成两句不同的话。
- **"回到这里"不存快照，只截断**（`doRollback()`）。消息数组是 append-only 的（每轮 push user + assistant），
  所以回滚 = `messages.length = idx`，那个下标就是全部状态 —— 存副本反而会和主数据不同步、
  还得管配额（每轮存一整份是平方增长，`chrome.storage` 默认只有 10MB）。
  两条容易漏的坑：① 截断后如果一条消息都没了，要把 `title` 复位成"新对话"，否则下一轮起名时
  会因为 `title !== '新对话'` 而永远不更新；② **必须连"正文和上面那条完全相同"这类标记一起丢**
  （它们挂在消息上），否则模型会去找一条已经不存在的消息。改这块时自检里那五条要全绿。
- **划词送进来的选段不进输入框，而是挂成 chip**（`state.sel`）。理由：选一段长文把正文灌进输入框，
  输入框就废了（没法在中间写自己的话）。发送那一刻才拼进 `full`：**你打的字在前**，
  再是「提示词 + ```围栏``` 包住的选段」—— 围栏是给模型的边界提示。围栏长度由 `askSelection()`
  截到 8000 字（和原来的划词上限一致，超了会提示）。同一段 + 同一动作去重（手快连点两下不会挂两块）。
- **「推荐图片」靠一段标记传**（`RECO_SYS` / `splitReco()` / `renderReco()`）。开关打开时请求里会多
  一条 system 消息，要求模型在回答末尾附 `<img-reco>词一 | 词二</img-reco>`；面板把这行从正文里**剥掉**，
  渲染成气泡底部那几个可点的小块（用真的 `<a target="_blank">`，不吃 CSP，右键还能复制链接）。
  六个容易漏的点：① 流式到一半时标记还没闭合，**也要剥**（否则用户会看着标签一个字一个字长出来）；
  ② 剥完前后两段要接回来 —— 模型不一定老实放在最后；③ 关键词限长 60 字、限 5 个；
  ④ 模型没给词就**不显示那一行**，不硬凑；⑤ **发给模型的历史里也剥掉**，否则它会把这当成"格式示范"，
  关掉开关后还继续写；⑥ 判断"这轮有没有要求"要看 system 里那句特有措辞，
  **不能搜 `img-reco` 就完事** —— 历史回答里本来就可能有这个标记。
  自检覆盖：`node docs/test-render.js` 里 8 条纯函数用例 + `selftest-key.html` 里 8 条端到端断言。
- **API Key 只从 `chrome.storage.local` 读，不从代码里读**（`loadKey()`）。`config.js` 里那个
  `apiKey` 只作**兼容**：浏览器里没存就用它，两条都空才拦你。每次 `send()` 前重读一遍（很便宜），
  换来的是"设置页改完回面板立刻生效，不用刷新页面"。设置页（`options.js`）自己建界面、
  自己写 storage；它加载的是**同一份 `config.js`**，所以 `apiBase` 这类改动两边一致。
  往请求头里塞 Key 只有一处（`callAPI()`）—— 别在别处再取一次，否则迟早出现"这边有 key 那边没有"。
- **别把真 Key 抄进 `docs/`**。自检页里要样例就编一个假的：那些页面是给人看、给截图用的，
  真 key 混进去就等于跟着截图一起外流了（`docs/selftest-key.html` 里原来就踩过这个坑）。
- **划词按下的瞬间要把文字记下来**（`selCache`）。在线文档 / PDF 阅读器这类页面会自己处理
  `mousedown`，等 `click` 时再去读 `window.getSelection()` 可能是空的，同样表现为"点了没反应"。

### 如果 `--screenshot` / `--dump-dom` 不出东西了（2026-10-12 遇到）

症状很有迷惑性：**进程起得来、profile 目录也建全了，就是零输出**，连 `--print-to-pdf` 也是。
换 Edge 一样。这时候别去调参数，**改走 DevTools 协议**——`--remote-debugging-port` 那条路是好的：

```bash
"$CH" --headless=new --disable-gpu --no-first-run --no-proxy-server \
  --user-data-dir="$TMP/dcdp" --remote-debugging-port=9333 --remote-allow-origins=* \
  "file:///$EXT/docs/selftest.html" &
CPID=$!
for i in $(seq 1 25); do
  curl -s --noproxy '*' --max-time 2 http://127.0.0.1:9333/json/version >/dev/null && break
  sleep 1
done
node docs/cdp-dump.mjs "selftest.html" "$TMP/r1.json" "$TMP/s1.png"   # 取结果 + 截图（三个页面分别跑）
kill $CPID
```

三个要点，缺一个就白折腾：

1. **必须和启动写在同一条命令里**。后台任务（`run_in_background`）会在那次工具调用结束时
   被整棵回收 —— 留一个 Chrome 在那儿等下一次调用是不可能的。
2. **`--no-proxy-server` 不能省**（这台机器有系统代理，Clash 之类）。
3. `curl` 加 `--noproxy '*'`，否则本机请求也会被代理绕出去。
